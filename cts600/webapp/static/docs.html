CTS600 dashboard v1.0

A web dashboard that reads and controls a Nilan CTS600 HVAC controller over its RS485/Modbus RTU bus, next to the original control panel.

Requires the panel's menu language set to Finnish. Screen recognition — the idle screen's mode, the NÄYTÄ DATA ("SHOW DATA") menu, and settings-change verification — is matched against Finnish menu text. In another language, mode detection returns "unknown" and the guarded key-press sequences (Update, settings changes, automatic re-anchor) stop on the first unrecognised screen. There's no language-switch support.

System architecture

The CTS600 controller and its physical control panel talk to each other over a two-wire RS485 bus using a vendor-specific Modbus RTU variant. This host taps onto the same bus, passively at minimum, and optionally also transmits, emulating a second control panel (button presses).

User guide

Panel page

Shows the panel's display (reassembled from the live display registers), with the idle screen's flags spelled out next to it (W = water heating, * = ventilation boost), the status LED, and, when started with --enable-control, the six buttons (On/Off/Up/Down/Enter/Esc). Each press is timed into the quiet gap between the panel's own exchanges with the controller.

UI model, confirmed against the real panel: the idle screen is read-only until you press Enter — that's what cycles which field is selected (temperature → mode → fan). Only then do Up/Down adjust the selected field. Esc discards an in-progress edit; Enter confirms/saves it. Up from idle shows NÄYTÄ DATA ("SHOW DATA"), and Enter opens the readings list.

Näytä data ("Show data") readings

Six temperatures: room (T15), outdoor (T1), tank top (T11), tank bottom (T12), heating supply (T14) and condenser (T5). Each is read live from the controller's input registers and anchored to the panel's own reading of it, which the NÄYTÄ DATA ("SHOW DATA") screens show whenever anyone navigates there (see below). A card that reads live says live; one whose register value can no longer be trusted shows the panel's last value with press Update under it, and hovering says why. The panel readings are kept in data/display_readings.json across restarts.

Update walks the menu once to refresh all of them (about a minute): Up, Enter, Down through the list, then Esc back to idle. The panel's display follows along while it runs, and the dashboard buttons are refused until it's done.

The walk stops and presses nothing more if the panel isn't on the idle screen at the start, if a key was pressed on the physical panel in the last 10 seconds or during the walk, if a press lands on an unexpected screen or doesn't change the screen, or if bus health degrades. The reason is shown under the Update button. If it stops inside the menu, the panel returns to idle by itself after about 2 min 45 s.

Diagnostics page

Frame and CRC counters, the currently recognised screen, the registers and bits seen in the cyclic traffic, the device info from the power-up REPORT_SLAVE_ID handshake, and the live frame log. The note box adds a timestamped marker to the log (and to the capture file, if one is enabled).

Running it

python -m cts600 --port /dev/ttyS0 --http-host 0.0.0.0 --http-port 8600 \
    --enable-control --rts-direction

Then open http://<host>:8600/. Serial port autodiscovery (the default without --port) only looks in Linux-style device paths (/dev/serial/by-id/*, /dev/ttyUSB*, etc.) — on another OS, pass --port explicitly. --rts-direction is only needed on hardware where the RS232-to-RS485 converter requires manual transmit-enable toggling. Without --enable-control the dashboard only listens: no buttons, no Update, and nothing is ever transmitted. With it, besides button presses and Updates, the dashboard also polls the temperature registers every --sensor-poll-seconds (default 10s) and, when a sensor's tracking is lost, automatically walks to the condenser screen to re-anchor it — both of those run on their own schedule, not just on user action.

Home Assistant integration

homeassistant/custom_components/cts600 is a Home Assistant integration for this service. Unlike the reference integration (github.com/Produce2727/nilan-cts600-homeassistant), which replaces the panel and opens the serial port from Home Assistant itself, this one leaves the physical panel in place: this service stays the only program on the bus, and Home Assistant talks to it over the network (/ws/status push, with a 60 s poll as fallback). All the bus safety — quiet-window timing, bus-health checks, stopping when someone uses the panel — stays in one place, here.

Run the service reachable from Home Assistant with --enable-control and --http-host 0.0.0.0 (it has no authentication, so keep it on a trusted network), copy homeassistant/custom_components/cts600 into Home Assistant's config/custom_components/, restart Home Assistant, then add the "Nilan CTS600 panel bridge" integration with this service's host and port.

It adds a climate entity (mode, setpoint, fan speed — the same POST /api/settings guarded key-press flow as the dashboard buttons), sensor entities for the six NÄYTÄ DATA ("SHOW DATA") temperatures plus operating state, binary sensors for the compressor/alarm/water-heating/ ventilation-boost flags and bus health, and buttons for Update and Cancel. Options let readings refresh on a timer (off by default) and mark them unavailable after a configurable age.

Known unknowns

All six NÄYTÄ DATA ("SHOW DATA") temperatures now have a confirmed register (input registers 0x0000–0x000F, one low byte each — see sensor_regs.py), so none of them are register-unidentified. Negative outdoor temperatures haven't been observed yet, so that reconstruction is unverified below 0 °C. The setpoint range accepted by POST /api/settings (5–30 °C) is a guessed guard rail, not the panel's actual documented range, which is unknown. The Finnish-only menu language requirement above has no workaround yet.
